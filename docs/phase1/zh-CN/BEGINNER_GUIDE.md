# 硬件小白入门指南：从“看懂”到安全跑通第一条数据链

**配套英文工程基准：** [Phase-1 package](../README.md)  
**适用对象：** 第一次接触 ESP32、工业传感器、RS485、I2C 和树莓派的人

这份指南帮助你理解现有设计，不改变任何已确认的电气参数。真正接线时必须使用 [逐线接线表](WIRING_AND_GPIO.md) 和对应英文工程页，不能只凭本页的比喻操作。

## 1. 先认识五个角色

把系统想象成一条快递链：

| 角色 | 在系统里是什么 | 类比 |
|---|---|---|
| 传感器 | 测量水中溶氧、pH、温度等 | 写出检测结果的实验员 |
| 接口/隔离板 | 把 RS485、RS232 或 I2C 变成 ESP32 能安全理解的信号 | 翻译员兼隔离门 |
| ESP32 | 定时问传感器、加时间和编号、断网缓存 | 现场记录员 |
| MQTT/Wi-Fi | 把消息送到树莓派 | 有回执的快递 |
| Raspberry Pi | 接收、检查、入库、画图 | 档案室和监控室 |

第一阶段最重要的是：每一份“快递”都要有身份、时间和原始内容；快递暂时送不到时应留在 ESP32，不能丢掉，更不能用 0 冒充。

## 2. 电压不是“越大越有力”这么简单

电子模块规定多少电压，就只能给它允许的电压。

- 工业传感器多使用 12 V 电源。
- ESP32 开发板由 USB 5 V 供电。
- ESP32 的信号脚工作在 3.3 V 逻辑。
- SLF3S-4000B 流量计电源只能在 3.2–3.8 V；5 V 可能损坏它。

“5 V 电源能提供 3 A”表示它最多有这个供电能力，不表示它会强迫设备流过 3 A。设备实际取多少电流由负载决定。但电压必须匹配，极性也必须正确。

### V、A、W 是什么

- `V`（伏特）：可以粗略理解为推动电流的“压力”。
- `A`（安培）：实际流过的电流。
- `W`（瓦）：功率，直流中通常约为 `V × A`。
- 例如 SEN0681 标称 0.2 W、12 V 时，电流约为 `0.2 / 12 = 0.0167 A = 16.7 mA`。

这个换算用于电源预算，不能替代实测，也不能拿平均电流掩盖电机启动峰值。

## 3. 正极、回路和“地”为什么不能乱接

电流要从电源正极流出，再通过回路线回到电源负极。项目里有多个不同参考地：

- `LGND`：某个 ESP32 节点的逻辑地；
- `SGND12`：12 V 传感器电源回路；
- `IGND4`：Node 4 隔离后的 I2C 侧地；
- Pi ground：树莓派自身参考地。

它们不因为都叫 GND 或都用黑线就可以任意相连。现有设计明确禁止外部短接 `SGND12 ↔ LGND` 和 `IGND4 ↔ LGND`。

> 为什么：长传感器线、水中电极、不同 USB 电源之间可能存在微小电位差。硬连在一起会形成地环路，可能造成读数漂移、通信错误，甚至让不该流经探头或 USB 的电流流过去。

## 4. 隔离是什么

隔离接口允许信息跨越，但不让两边的地线直接导通。本项目里：

- `Waveshare TTL TO RS485 (B)`：隔离 RS485 与 ESP32 UART；
- Waveshare Industrial Isolated TTL to RS232 (B)：隔离 H2S 的 RS232；
- `DFR0565`：隔离 Node 4 的 I2C 泵/流量总线；
- Atlas `ISCCB-2`：隔离 pH/EC 探头电路。

断电后用万用表电阻/蜂鸣档检查隔离两侧，设计要求的禁接对应该为开路。不要为了“蜂鸣才放心”而把隔离两边主动短接。

## 5. 四种常见通信接口

| 接口 | 你可以怎样理解 | 本项目注意点 |
|---|---|---|
| UART/TTL | ESP32 内部附近使用的单端串口 | 只有 0–3.3 V 逻辑；不能直接接真正的 RS232。 |
| RS485 | 适合工业传感器和长线的差分总线 | 通过 Waveshare TTL TO RS485 (B) 隔离；A/B 名称在厂家间可能不统一。 |
| RS232 | 电平和 TTL UART 不同的串口 | S1-1020 必须使用隔离 RS232 转换板，不能直接接 GPIO。 |
| I2C | 近距离、同盒内多器件的两线总线 | SDA/SCL 要有正确上拉；Node 4 还要隔离并降到 3.3 V。 |

### TX 和 RX 怎么接

通常发送 `TX` 接收端 `RX`，接收 `RX` 接发送端 `TX`。Waveshare 标签从转换器自身方向命名：TTL `RXD` 是输入，由 ESP TX 驱动；TTL `TXD` 是输出，接 ESP RX。必须按逐线表接，不能只靠字母猜。

### RS485 的 A/B 如果没响应怎么办

不能带电随便对调。先依次核实电源、地址、波特率、校验位、命令字节和 CRC。只有这些都正确仍无有效响应时，断开两端电源，只交换 A/B 两线，再重试并记录最终极性。

## 6. 保险丝是保护线和故障范围，不是“调电流”的旋钮

每个 12 V 分支先用 1 A 保险丝，主路按设计使用 2 A 保护。保险丝熔断说明可能有短路、接反、线缆损伤、电机堵转或启动浪涌，不能简单换更大保险丝。

六个 12 V 分支是：

- `DO1`：SEN0681；
- `MID_AUX`：条件性的 SEN0710/SEN0711；
- `RDO`：RDO Blue；
- `ORP`：条件性的 SEN0709；
- `H2S`：条件性的 S1-1020；
- `BYPASS`：EZO-PMP 电机。

分支保险丝额定值相加可以大于电源额定值，因为主保险和电源限制总电流；分支保险主要负责把局部故障隔离开。

## 7. 常见实体零件的作用

| 零件 | 作用 | 新手常见错误 |
|---|---|---|
| 冷压端头（ferrule） | 把多股软线压成可靠端头，再进螺丝端子 | 用焊锡把线头镀硬后夹进端子，时间久了可能松。 |
| WAGO 221 | 在干燥盒内分配同一个电气网络 | 把正极和负极放进同一只连接器。 |
| 电缆格兰头（cable gland） | 固定和密封穿箱电缆 | 不量电缆外径就买，导致夹不紧或穿不过。 |
| 滴水弯（drip loop） | 让沿线缆流下的水先滴落，不进箱 | 线缆一路向上直进盒，水被引进盒内。 |
| 双绞线 | 减少 RS485 和电机回路的干扰 | 把泵电机线与信号线长距离捆在一起。 |
| 屏蔽层 | 截获外界噪声 | 两端都接地，反而形成环路。 |

## 8. 万用表最先学的三项检查

### 8.1 断电连续性检查

用途：确认某根线确实从 A 到 B，也确认禁止相连的两点没有短路。

1. 全部电源拔掉；
2. 电容放电后再测；
3. 先短接表笔确认蜂鸣功能正常；
4. 按线号逐根核对；
5. 对 `SGND12 ↔ LGND`、`IGND4 ↔ LGND` 等禁接对测量，应为开路；
6. 记录结果，不只说“看起来没问题”。

不要在带电电路上使用电阻/蜂鸣档。

### 8.2 直流电压检查

1. 黑表笔插 `COM`，红表笔插电压孔；
2. 选直流电压档；
3. 黑表笔接该电压域的回路参考，红表笔接正极；
4. 空载先测，再在最坏负载状态下测；
5. 注意读数正负号，负号往往表示表笔或极性相反。

关键读数包括 12 V、USB 5 V、外置 3.3 V，以及 Node 4 流量计处实际 3.2–3.8 V。

### 8.3 电流检查

电流档必须把表串联进回路，接法错误会直接短路。第一次测电机启动电流或不熟悉电流档时，应由有经验的人操作，优先使用有电流限制的台式电源或合适的电流测量工具。

## 9. Release A：第一次上手只做这一条

目标：让 SEN0681 的真实溶氧数据稳定进入树莓派数据库和 Grafana。

### 第 0 步：不接电，做纸面和实体核对

- 收货标签必须是 `ESP32-S3-DevKitC-1-N8R8`、`Waveshare TTL TO RS485 (B)`、`SEN0681`；Waveshare料号为23778。
- 核对 SEN0681 线色：棕 = 电源正、黑 = 电源回路、黄 = RS485 A、蓝 = RS485 B。
- 核对 Waveshare 的 TTL 逻辑侧和隔离 RS485 侧；确认 `120R` 开关初始处于 OFF。该转换器没有12 V传感器输出端。
- 每根导线两端都贴同一个 wire ID。
- 按 [逐线接线表](WIRING_AND_GPIO.md) 做连续性和禁接检查。

### 第 1 步：只上 ESP32 USB 电源

- 不接 12 V 传感器；
- 确认 ESP32 正常启动，USB 串口可用；
- 测 `P5V` 和外置 Pololu `P3V3`；
- Wi-Fi 发射时不应出现 brownout（欠压复位）。

### 第 2 步：只加入 Waveshare 转换器的 TTL 逻辑侧

- `P3V3 → +`，`LGND → -`；
- ESP GPIO17 TX → Waveshare TTL `RXD`；
- Waveshare TTL `TXD` → ESP GPIO18 RX；
- 再次确认隔离侧 GND 与 `LGND` 不导通。

### 第 3 步：单独给 SEN0681 上 12 V

- 1 A `DO1` 分支；
- 棕线接 `+12V_DO1`，黑线接 `SGND12`；
- 黄线接 Waveshare `A+`，蓝线接 `B-`；
- Waveshare隔离侧 `SGND` 接 `SGND12`；
- 上电前复测极性、电压和短路。

### 第 4 步：只验证传感器通信

- Modbus RTU：地址 1，4800 baud，8N1；
- 每条命令间隔至少 200 ms；
- 连续获取 100 帧 CRC 正确的响应；
- 保存原始请求/响应字节，不只看解码后的数值；
- 把实际测得的盐度写入 `0x1020` 并读回，不能默认用 30 ‰。

### 第 5 步：接入树莓派链路

- ESP32 为每条测量加入 UTC、`boot_id`、`sequence_number`、传感器 ID 和 QC；
- 通过 MQTT QoS 1 发布；
- 树莓派把原始字节先持久化，再发应用层 ACK；
- 检查 PostgreSQL 中的原始记录、解码记录和 Grafana 图；
- 断 Wi-Fi 至少 4 h，再恢复，确认按原顺序回放且不重复生成科学读数。

### 第 6 步：连续运行

- 通过重启、断网、数据库暂时停机、树莓派断电恢复测试；
- 连续 72 h 运行；
- 核对时钟、序号缺口、通信错误、缓存容量和数据完整率；
- 只有通过后才加入下一只传感器。

## 10. 为什么缺失值不能写成 0

溶氧 0 mg/L 是一个严重且可能真实的科学结果；“传感器没回复”是通信失败。两者完全不同。

正确记录方式：

```text
value = null
qc_flag = COMMUNICATION_ERROR
raw request/error preserved
```

错误方式：

```text
value = 0
```

后者会让研究人员误以为水里真的没有氧，并破坏后续分析。

## 11. 为什么要同时保存时间、序号和原始字节

- UTC 告诉你测量发生在现实世界的什么时候；
- gateway received time 告诉你数据什么时候到树莓派；
- `boot_id + sequence_number` 在时钟失准时仍能确定顺序和查缺口；
- 原始字节让你以后能重新检查当时是不是解码错了；
- QC 告诉你数值存在什么风险，而不是删除它。

## 12. 什么时候必须请有经验的人帮忙

- 任何市电、插座、GFCI/RCD、配电设施工作；
- 需要测量电机启动电流而你不熟悉串联电流测量；
- 需要使用接地示波器跨隔离边界测量；
- 发现盒内进水、腐蚀、焦味、过热或保险丝反复熔断；
- 不确定设备外壳、屏蔽层或保护地该接哪里；
- 厂家文档与实物端子、线色或料号不一致。

最安全的原则不是“尽量接上看看”，而是每次只增加一个已核实部件，并在通电前证明电压、极性、连通关系和隔离边界都正确。

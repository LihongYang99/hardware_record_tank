# Jetson 调试相机网络：命令与排错记录

日期：2026-09-22。范围：lab_scale 局域网连通性测试，不改变 Raspberry Pi 为正式网关的架构。

## 最终成功方案：命令速查

用户在修正地址后确认“成功，有返回”。下面集中整理当次修正与探测步骤；不是逐字保存的终端历史，成功回包原文尚未归档。

**前提：Jetson 已连接实验室 Wi-Fi，相机通电并接路由器 ether5；网卡名为 `wlP1p1s0`（P 大写），`192.168.1.200` 未被其他设备占用。**

当次先删除输错的地址（只有存在这个错误地址时才执行）：

```bash
sudo ip addr del 192.158.1.200/24 dev wlP1p1s0
```

随后使用正确地址并测试：

```bash
sudo ip addr add 192.168.1.200/24 dev wlP1p1s0
ip -br -4 addr
ping -c 4 192.168.1.88
```

关键修正是 **192.168，不是 192.158**。保留原来的 `192.168.88.254/24`，新增的是 Jetson 的第二个 IP，不是修改相机 IP。用户报告此后探测有回应；没有证据宣称视频已经播放。

再次使用时先运行 `ip -br -4 addr`：如果正确的附加地址已存在，跳过 `add`，直接运行 `ping`。若重启/重连后地址消失，再按前提添加；不需要重新制造或删除历史错误地址。

后续身份核对命令（结果仍待保存，不算作已验证成功的 MAC 对照）：

```bash
ip neigh show 192.168.1.88
```

`dev wlP1p1s0` 的意思是“在名为 wlP1p1s0 的网卡上操作”。无需安装 arping，无需外网。以下章节保留各命令解释、失败原因和撤销操作。

相机保持通电，以太网接 MikroTik 路由器 `ether5`；Jetson 通过实验室 Wi-Fi 接同一路由器。本次用户改为相机单独供电后看到 ether5 的 R 标记；不据此宣布原 PoE 注入器路径测试通过。

| 对象 | 本次记录 | 说明 |
|---|---|---|
| 路由器 | `192.168.88.1` | 实验室 LAN |
| Jetson 无线网卡 | `wlP1p1s0` | **P 大写**，其余按实际输出；名称区分大小写 |
| Jetson 原 IP | `192.168.88.254/24` | 截图实测，不是相机或 ESP 的地址保证 |
| Jetson 临时附加 IP | `192.168.1.200/24` | 只用于本次测试；使用前确认未被其他设备占用 |
| 相机目标 | `192.168.1.88` | 标签默认地址，本次用户报告探测有回应 |

访问局域网相机不需要外网。相机与 Jetson 在相同二层网络且没有隔离时，给 Jetson 增加相机网段地址，可直接访问，不必修改路由器 LAN 或 ESP 地址。下列命令在 **Jetson 的终端**运行，不是在 Mac 或 RouterOS 中运行。

## 1. 查看 Jetson 地址与路由（只读）

```bash
ip -br -4 addr
ip -4 route
```

- `-br`：简洁显示；`-4`：只看 IPv4；`addr`：网卡地址；`route`：路由表。
- 本次学校网截图为 `10.141.50.5/23`，回实验室 Wi-Fi 后为 `192.168.88.254/24`。
- `lo` 的 `127.0.0.1` 是本机回环；`docker0` 的 `172.17.0.1` 是容器网络，不是相机。
- 在实验室网络才进行以下步骤；不能在学校网扫描相机。

## 2. 添加临时同网段地址

前提：确认网卡名为 `wlP1p1s0`，且实验室没有其他设备占用 `192.168.1.200`。占用情况不清楚时先确认，不把此地址作为通用固定值。

```bash
sudo ip addr add 192.168.1.200/24 dev wlP1p1s0
ip -br -4 addr
```

`sudo` 使用管理员权限；`add` 是增加，不是替换原地址；`dev` 指定网卡。成功通常没有文字输出。输入 sudo 密码时终端不显示字符。

检查无线网卡一行同时包含：

```text
192.168.88.254/24 192.168.1.200/24
```

这是预期地址片段，不是保存的成功原始日志。此配置未写入持久网络配置，重启或重新连接可能丢失；不要反复添加，若提示已存在先检查地址。

## 3. 探测相机并核对设备身份

```bash
ping -c 4 192.168.1.88
ip neigh show 192.168.1.88
```

- `ping -c 4`：向目标发送四次 ICMP 探测。回复说明该地址有设备响应，不等于视频流可用。
- `ip neigh show`：查看邻居表中的 IP→MAC 对应关系。核对是否为之前 ether5 上的 `00:12:34:C6:67:04`。
- 没有 ping 回复不能单独证明相机故障；需结合邻居表、链路和设备设置判断。
- 若邻居表为空、INCOMPLETE 或 FAILED，不宣称 MAC 已确认。保存实际输出后继续排查。

## 4. 本次实际遇到的错误

| 提示/现象 | 本次解释与处理 |
|---|---|
| `Object "abbr" is unknown` | 将 `addr` 错写成 `abbr`；用 `ip -br -4 addr` |
| `Option "-addr" is unknown` | `addr` 前不加减号 |
| `Cannot find device` | 网卡名输错，包括大小写；以 `ip -br -4 addr` 输出为准；先前指导也曾把大写 P 写成小写 |
| 地址出现 `192.158.1.200/24` | 把 **168** 输成 **158**，没有进入相机所在网段 |
| `From 192.168.88.1 ... Destination Net Unreachable` | 本次错误地址状态下请求仍走路由器，路由器返回不可达；不能据此判断相机损坏 |
| `arping: command not found` | 工具未安装成功，与相机是否在线不是一回事；本次最终流程未依赖 arping |

仅当确认添加了本次错误地址时，删除它，再添加正确地址：

```bash
sudo ip addr del 192.158.1.200/24 dev wlP1p1s0
sudo ip addr add 192.168.1.200/24 dev wlP1p1s0
ip -br -4 addr
```

任何命令报错时先查看输出，不继续盲目重复。不要使用 `ip addr flush`，也不要删除原来的实验室 LAN 地址。

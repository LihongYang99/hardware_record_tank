## 方法与原理

### 方法

1. **硬件链路**。浊度探头输出 RS485，经一块 TTL↔RS485 转换器变成 3.3 V 串口，接 ESP32 的 UART1（RX GPIO18 / TX GPIO17）。探头由 12 V 供电，ESP32 由 USB 5 V 供电。
2. **协议**。Modbus RTU，地址 1，4800 bps / 8N1（出厂默认）。每 4 s 发一次功能码 03、从寄存器 0 读 2 个：寄存器 0 是浊度（无符号，÷10 得 NTU），寄存器 1 是温度（有符号，÷10 得 °C）。
3. **解析与上传**。先校验 CRC 和帧长，再解码；原始字节 `raw`、序号、请求/接收时刻一起写成一行，经 Wi-Fi/MQTT 发到 Jetson，落库后 ACK。和 Node-1 完全相同。

### 原理

- **浊度测的是什么**。探头向水中发光，测量被水中颗粒散射回来的光（光学散射法），单位 NTU。它反映水"有多浑"：残饵、粪便、藻类和底泥扰动都会让它升高。
- **为什么只报 NTU、不报悬浮物浓度**。NTU 与悬浮物质量浓度（mg/L）的关系取决于颗粒大小、颜色和形状，每个水缸都不同。只有在本缸取水样称重、建立对照关系之后才能换算（SPEC、Phase-1 资料都这样要求），在那之前网页只显示 NTU。
- **为什么只读不写**。地址、波特率、校准和偏差修正都能通过寄存器改写；固件一律不写，改设定必须人工操作并记录，和 Node-1 同样的原则。
- **为什么单独一个节点**。浊度探头出厂地址也是 1，和 DO、ORP 冲突；单独一块 ESP32 和一条 RS485 总线，不用改探头地址，一个探头掉线也不影响其他节点。
- **温度通道**。这是探头内部温度，可以辅助判断探头是否在水里，但它的量程和精度资料里没写清，**不作为水温数据使用**，也不做范围检查。
